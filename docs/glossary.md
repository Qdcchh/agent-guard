# 对外名称与术语表（唯一来源）

2026-10-19 起生效。**所有对外材料**（演示页面、汇报说明、论文、README 首屏、桌面启动器、PPT）只用本表"对外名称"。修改流程见 [改名修改指导](rename-guide-20261019.md)。

定名原则：
- 有行业标准名的直接用标准名；没有的就写成"动作 + 对象"，让人看名字就知道它做什么。
- 同一个东西全文只用一个名字，不混用近义词。
- 内部代号只留在开发文档（`tasks/`、历史 `docs/`）里，不进对外材料。
- 代码标识符、事件类型、拒绝码、HTTP 头、包名都**不改**，本表只管显示文字。

为什么叫"会签"：办公场景里，一笔开销要几个部门各自盖章才生效。本项目里，一笔下单的 SM2 签名必须由授权服务器侧和网关侧各出一半才能形成，而授权服务器侧在出这一半之前会查委托链、撤销和预算。"会签"这个词国内办公人员和密码行业都能一眼看懂。

英文仅在必须时使用 `HuiQian`（注意 GitHub 上已有不相关的考勤项目"慧签 HuiQian"，所以对外材料以中文名为主）。仓库名、Python 包名 `agent_guard`、证书 CN 等技术标识**不改**。

## 2. 对外统一说法（卖点）

**一句话：**
> 代理被提示注入骗了，也花不出授权以外的一分钱；就算网关被攻破，也伪造不出下单签名。产出的是标准 SM2 签名，下游用任何国密库都能验。

**三个卖点（按顺序讲）：**
1. **不靠识别攻击**：护栏类产品要先认出恶意输入；本项目不需要认出来，越权请求在网关和签名环节会被确定性拒绝。
2. **网关不再是单点**：下单签名的私钥拆成两半，授权服务器侧那一半只有在委托链、撤销、预算都检查通过时才给出。传统 SM2 协同签名的服务端只核对"是不是本人"，本项目核对的是"这一笔现在还有没有被授权"。
3. **接入成本低**：不改模型，下游只做标准 SM2 验签。

局限照常写，但放在卖点之后讲，不放在开头。

## 4. 机制与概念（所有材料通用）

| 旧 | 新 | 一句白话 |
|---|---|---|
| 可信执行 / 可信授权执行 | **删除不用** | 密码圈里"可信执行"特指 TEE（SGX/TrustZone），会被误解成硬件方案 |
| 可验证授权 | 授权检查 | |
| 双域共签 / 双域协同 SM2 / COSM2 | **SM2 两方协同签名**，简称"协同签名" | 下单签名的私钥拆成两半，两边合作才签得出 |
| 授权即密钥 | 先查授权再签名 | 授权侧查过才出它那一半签名 |
| 授权谓词 / 谓词门控 | 授权检查条件 | 委托链、有效期、撤销、范围、预算、策略版本 |
| 授权状态承诺 | **撤销名单快照** | 授权服务器定期发布带版本号、经 SM2 签名的撤销名单摘要，签名里写入版本号，下游离线就能判断新旧（类似证书的 OCSP 装订） |
| 持有者绑定 / 发送者约束 | 令牌防盗用（持有者证明） | 每次请求用持有者私钥签名，光有令牌没用 |
| AGPoP / AG-Proof | 请求证明 | 对外正文只说"请求证明"；技术细节处可括注"（协议字段 AG-Proof）" |
| 委托收窄 | 委托降权 | 转给下级的权限只能更小 |
| 动态撤销 | 撤销实时生效 | |
| 接受事务 | **受理事务** | 网关受理时在数据库里一次性完成检查与预留 |
| 付款意图共签 | 付款批准（协同签名） | |
| ag-approval | 下单批准签名 | |
| GM-MVP-1 | 国密配置 v1 | |
| 基础防线 / 三道防线 / 核心机制 / 更多保障 | 见 3.1，不再用"防线""核心机制" | |
| 智能体 / 多智能体 | **AI 代理** / 多个 AI 代理 | 全文统一；论文首次出现写"AI 代理（智能体）" |

以下保持原样：OAuth、OIDC、Token Exchange（RFC 8693）、DPoP（RFC 9449）、SM2、SM3、FROST、Ed25519、门限签名、半诚实模型、幂等、重放、x402、EIP-3009、签名回执、审计检查点、run_id。这些都是标准名或业内通用词。
