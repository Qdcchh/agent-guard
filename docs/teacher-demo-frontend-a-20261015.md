# A 前端：演示页说明与交接（2026-10-16 重做版）

本文替换 10 月 15 日 GPT 版前端的说明。旧界面已整体弃用；它的文件仍保存在提交 `c1327d9` 中，需要时可从 git 取回。本轮只改了 `web/teacher-demo/` 三个文件、前端逻辑测试和文档，没有动服务端、场景适配、协议核心或任何历史验收证据。项目整体仍为 PARTIAL。

## 怎么打开

在仓库根目录运行 `python3 tools/teacher_demo_server.py`，然后打开 `http://127.0.0.1:8765/`。端口被占用时加 `--port 8766`，地址也换成对应端口。必须用 `127.0.0.1` 访问，用 `localhost` 会被服务端拒绝。现场运行需要 Docker Desktop 正在运行。

快捷键：`0` 系统总览，`1`–`7` 对应场景，`←` / `→` 单步，空格播放，`Esc` 关闭模块说明。也可以直接打开 `#s1`、`#threshold`、`#evidence` 这类地址进入对应章节。

## 页面结构

每一页左栏讲"是什么、为什么"，右栏讲"怎么运行"，中间一条细分割线。

| 章节 | 内容 |
|---|---|
| 系统总览 | 三层系统模型（代理层、可信授权执行边界、业务与证据）。连线写明协议：OIDC 登录 + PKCE、授权码交换与 Token Exchange、AGPoP 令牌 + AG-Proof、接受事务、幂等执行、签名回执。门限签名与 x402 用虚线表示未接入。 |
| 场景 1 / 3 / 6 | 时序图：横向是谁发给谁，纵向是先后。拒绝发生在哪个参与方，驳回印章就盖在哪条生命线上，下方给出拒绝码。左栏写用到的协议、和原有做法相比改了什么、诚实边界，以及该场景的真实记录与运行按钮。 |
| 其余场景（2 / 4 / 5 / 7） | 同一画法：篡改签名后的参数、两条分支共享预算、重放与业务幂等、下单成功后进程崩溃的恢复。 |
| 门限批准 | 设计示意：三个签名域、1/3 不足、2/3 聚合成组签名、批准后撤销仍被拒绝。页面标明"B 尚未交付"，没有对应的真实记录。 |
| 真实记录 | 七个场景的"读取记录 / 现场运行"、完整采购演示、原件与篡改副本的离线验证、三级预算表、回执状态与验证边界。全部来自 `/api/state`。 |

点击任何参与方按钮，左栏会换成该模块的六项说明：解决什么问题、谁调用、接收什么、检查什么、输出什么、证据与局限。

## 数据来源与诚实性

- 页面右上角始终显示当前画面的来源：示意推演、设计示意、现场运行、记录回放、真实记录、架构说明。图例在左栏底部。
- 时序图默认使用示意事件。示意事件的形状与 DemoEvent v1 完全一致，内容依据现有集成测试编写，例如场景 3 的申请值 `100001` 分、场景 6 的"撤销事务先持锁、接受排队、撤销提交、接受被拒"。拒绝码取自接口契约，并注明"接入事件流后显示实际返回"。
- 本机服务一旦在 `job` 中给出 `run_id`，页面就开始拉取 `/api/runs/{run_id}/events`，把示意事件替换为真实事件，来源标签同时改为"现场运行"或"记录回放"。接口尚未实现时返回 404，页面安静地继续显示示意内容。
- 事件只按 `seq` 排序、按 `event_id` 去重；出现缺口时等待补齐并在说明条中提示；断线时画面停在最后收到的事件，不会继续推进。
- 浏览器不保存任何令牌、私钥或凭据，不使用浏览器存储。页面只调用服务端已有的固定动作。

## 需要 B 配合的部分

字段与词表见 [DemoEvent v1 前端对接需求](demo-event-v1-frontend-needs-20261016.md)。B 需要做三件事：在 `/api/state` 的 `job` 中加 `run_id`；实现只读的事件读取接口；在真实协议边界发出脱敏事件。场景 1、3、6 的最小事件序列已在该文档里按测试代码列出。

## 已知限制

- 没有在本轮重新执行七类 Docker 安全实验或完整采购；页面上的真实记录来自服务端返回，没有重跑就显示为未读取。
- 示意事件不是运行结果。在 B 的事件接口上线前，时序图里的每一步都只是讲解。
- 门限签名、x402、手动 OIDC 登录同意页面、真实大模型都没有接入。
- 1366×768 投屏时，场景页左栏可能需要滚动，较长的时序图（场景 3、5）会略微缩小。
- 老师提供的两条小红书视觉参考，本机网络无法访问，尚未据此核对节奏。
